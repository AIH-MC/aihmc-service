## 数据和运行文件

发布前备份数据库、材质目录、RSA 密钥、实际配置和当前网关设置，并确认恢复方法可用。不要把带删除数据库语句及业务数据的原 `db.sql` 当成升级脚本。

保留现有六表，不自动改表，不重新生成 UID、profile_id、player_uuid 或已有令牌。Go 的材质目录和网关静态目录必须指向相同的持久化数据；已有纹理 URL 的域名和路径保持可达。使用同一 RSA 密钥对，启动校验公私钥匹配。

运行配置放在受控目录中，秘密文件和私钥仅对运行账号开放读取权限，材质目录允许服务写入并由静态网关读取。真实 config.toml、秘密和私钥既不提交 Git，也不随 Actions 产物上传。发布包只包含 Go 可执行文件、配置模板和必要的说明。

## 网关配置核对

复用现有 TLS 证书和域名。下面是同机 Nginx 网关的配置片段，实际配置文件位置和材质绝对路径需按现网填写，不在未知主机上自动应用。

```nginx
location ^~ /textures/ {
    alias /absolute/persistent/textures/;
    default_type image/png;
}

location / {
    proxy_pass http://127.0.0.1:8080;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
}
```

`proxy_pass` 不附加替换 URI，保留客户端的路径和查询串。`X-Real-IP` 必须由网关覆盖，不能转发调用者自带的值。默认 Go 仅监听回环地址，与同机网关保持现有的主机信任边界；其他主机上的代理部署需先确认真实拓扑，不直接照搬此片段。

移除或停用原 PHP/FastCGI location 和根路径 try_files 入口，避免旧的正则 location 抢先处理请求。不要配置仓库根目录为公开的静态目录。除显式公开的材质目录外，请求交给 Go；config.toml、秘密、私钥、源码及后续的 archive 不得通过网关暴露。保留现有材质缓存规则，具体响应头需与现网基线核对。

## 切换步骤

1. 将已校验架构及校验和的 Go 产物部署到独立发布目录，保留可恢复的 PHP 发布版本。按目标系统的现有进程管理方式配置 Go 服务，不改写未知环境的管理脚本。
2. 迁移真实配置到 config.toml，核对数据库、UCenter、域名、时长、秘密文件和资源路径。在该主机执行 `--check-config`；日志不得包含密码、密钥和令牌值。
3. 在独立端口启动 Go，用元信息接口检查数据库访问与公钥，使用测试账号实际完成认证、刷新、进服、头像及材质加载。若使用 Qt 启动器，必须操作真实 Windows 窗口并检查中文及材质，禁止 offscreen。
4. 按批准窗口短暂收口新请求，等待 PHP 在途请求完成，记录数据库备份点和切换时刻。不要复制执行真实的登录、刷新、进服或删除写请求进行影子比较。
5. 将整条认证链路切到 Go，继续由网关提供既有材质路径。检查成功和失败场景、元信息、公钥、角色身份和已有令牌；确认记录的客户端 IP 正确。
6. 按约定观察成功率、进服结果、响应延迟、上游和数据库错误、资源占用及材质可用性。达到预先约定的回滚条件时立即回滚，不临时放宽标准。

从本机 PowerShell 通过已有 SSH 连接执行目标环境验证时，使用下列记录方式。此处的主机和路径仅为占位示例：

```powershell
& ssh deploy-user@server '/opt/aihmc-api/aihmc-api-linux-amd64 --config /etc/aihmc-api/config.toml --check-config' 2>&1 | Tee-Object -FilePath 'build.log'
$buildExitCode = $LASTEXITCODE
if ($buildExitCode -ne 0) {
    Get-Content -LiteralPath 'build.log'
    exit $buildExitCode
}
```

需要在目标主机编译或运行其他测试时，同样在前台通过 PowerShell 输出并记录日志，立即检查退出码。普通服务进程由已确认的现有管理方式运行，构建和测试不放到后台执行。

## 回滚步骤

先收口 Go 新请求并等待在途写操作完成，再将网关恢复至此前保留的 PHP 发布版本。使用原配置、密钥和同一业务库，检查原有及切换后签发的令牌、认证、进服、角色查询和材质路径。

常规代码回滚不恢复切换前数据库快照，以免抹掉 Go 运行期间的有效写入。只有明确确认数据损坏并获得数据恢复决策后，才执行独立的恢复方案；不得把代码切回误当成数据已恢复。

目标环境的回滚演练必须记录停止、收口、切换命令和时间、验证账号、结果及遗留项。本地令牌互认仅证明相关数据格式兼容，不能证明未知网关、未知生产数据和未知主机上的回滚已经通过。
